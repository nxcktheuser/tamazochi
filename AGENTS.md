# Правила работы с Tamazochi

## Перед изменениями
- Прочитай README.md и последние записи CHANGELOG.md, затем `git status` и `git log -5 --oneline`.
- При чистом рабочем дереве получи изменения текущей ветки через `git pull --ff-only`. При незакоммиченной работе сначала разберись, кому она принадлежит; не стирай и не прячь её автоматически.
- Если ветки разошлись, изучи обе стороны и согласуй смысл объединения. Не применяй force push или reset --hard для обхода конфликтов.
- Явные поручения пользователя определяют объём задачи. Не реализуй обсуждаемые идеи без поручения.

## Изменения и проверки
- Делай небольшие изменения с одной понятной целью.
- Комментарии в коде объясняют причины, ограничения и неочевидные решения; не пересказывают каждую строку.
- Проверяй затронутое поведение. Для документации достаточно проверить точность описаний, ссылки на файлы и diff.
- Не выдавай чтение кода за запуск приложения. Указывай, какие проверки действительно выполнены и что осталось непроверенным.
- Не добавляй секреты, личные заметки, локальные пути участников и файлы окружения в репозиторий.

## История и передача работы
- Сообщения коммитов пиши по-русски: `<тип>: <конкретное изменение>`. Типы: feat, fix, art, docs, refactor, chore.
- Пример: `art: добавить фон личной комнаты бункера`.
- Для нетривиального коммита добавь описание: зачем сделано, как изменилось поведение, что проверено, известные ограничения. Не записывай планы как выполненную работу.
- После значимого изменения добавь запись в начало CHANGELOG.md: дата, что/зачем, проверка, ограничения или следующий шаг при наличии. Мелкие подробности остаются в Git.
- Обновляй README.md, если меняются запуск, устройство проекта или его текущее состояние.
- В коммит включай только относящиеся к задаче файлы, перечисляя их явно при `git add`.
- Отправляй готовые проверенные коммиты только при разрешении пользователя на push. Разрешение на синхронизацию в текущей сессии действует до его отмены.
- После push проверь соответствие локального HEAD удалённой ветке. В отчёте укажи краткий результат, проверки и хеш коммита.
